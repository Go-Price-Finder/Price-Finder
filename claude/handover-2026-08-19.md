## 3. STANDING RULES in force

1. **DDL second-reader**: operator/Cowork writes migrations, session
   reviews (hash-verified), operator applies — via Supabase MCP/CLI,
   never the browser SQL Editor. Session code that consumes a column
   ships only after the column is applied and verified live.
2. **Credentials never in chat**; never print raw auth-endpoint bodies;
   never click AWIN tracking links (self-click).
3. **Nav and section ship together** — a nav item promises a section
   (gift-cards rule; §31).
4. **Flag-flip plus re-sync is ONE change** (§19b/§21): write-time
   flags (imageUsagePermission, status, comparisonEngineConfirmed) do
   nothing until affected rows are re-synced; the materialisation check
   enforces it.
5. **A positive control must be drawn from the population the claim is
   about** (§19). A control that cannot fail is decoration.
5a. **A measurement that is not REPRODUCIBLE across consecutive runs is
   not a measurement** (§39) — run any new check twice before believing
   it once. This outranks 5b: 46/51/53/55 with no code change was
   visible from run one, and no rule said to look.
5d. **Never record a near-miss as a catch** (§29). "Removed before it
   cost us anything" was written when nobody had checked whether it had;
   Search Console later showed three weeks of live exposure. A record
   claiming more safety than the evidence supports is the same defect
   class as the false claims we removed from the site — and it is worse
   in a ledger, because the ledger is what the next reader trusts
   without re-deriving. State exposure as UNKNOWN until measured.
5c. **Where an invariant can be stated, state it instead of a tolerance**
   (§39). "A font change must move contrast by EXACTLY ZERO" caught a
   5-node delta that no threshold would have flagged. Most of what goes
   wrong is small.
5b. **The first run of a NEW check is measuring the CHECK** until proven
   otherwise (§39) — any number a new instrument produces gets explained
   before it gets acted on. The contrast checker was wrong five times
   against two real defects; two thirds of its "debt" was its own.
   Corollary: a measurement that is not REPRODUCIBLE across consecutive
   runs is not a measurement.
5f. **Compare against OUTPUT, never against intent** (§48). That same
   gate's first version grepped app/sitemap.ts's SOURCE and reported
   seven partner pages as missing; they are emitted by a mapper and all
   seven are in the real sitemap. A check that reads intent invents its
   own failures. It now reads .next/server/app/sitemap.xml.body.
5e. **A check that enumerates by hand is a check with an expiry date
   nobody wrote down** (§48). check-contrast.mjs hand-listed its routes
   including exactly one guide; publishing the second put a live route
   outside the gate while the gate said PASS. Converted to enumerate the
   build output: 12 routes -> 29, and it immediately found a real 1.45:1
   failure live on every multi-image product page. Where a list carries
   policy judgement and cannot be derived, assert it is COMPLETE instead
   — `scripts/check-hand-enumerations.mjs` (postbuild) does that for the
   sitemap and for SCAN_DIRS.
5g. **An alarm that fires during normal operation is worse than no
   alarm** (§55c). It gets muted, and a muted alarm converts an absent
   signal into a false sense of coverage — the §19 shape again. Before
   adding one, NAME the normal operations that will trip it; a non-empty
   list means the alarm is mis-specified, not the operations. Caught on
   my own first row-count assertion, which would have 500'd the cron on
   every legitimate import day.
5h. **The tool that applies a migration must also write it** (§57b).
   Applying DDL through the MCP silently skips the file write; nothing
   failed and nothing warned while twelve migrations diverged from the
   repo over three weeks. A migration lands in the repo FIRST and is
   applied SECOND, or the applying tool writes it too. General form:
   when one action has two halves and only one is tool-enforced, the
   unenforced half is optional in practice whatever the process document
   says — the fix is never "remember", it is to make the enforced half
   fail without the other.
6. **Counts count, never fetch** (§17/§18): a read whose purpose is to
   measure uses `count: exact, head: true`.
7. **Full-inventory question on any component swap** (§32): "what did
   the replaced component do that the new one doesn't" — asked in full,
   not item by item.
8. Error handlers must not write success-shaped values (§24). Every
   unbounded read is paged via `lib/supabase/fetchAllRows.ts` or
   registered with a reason (§18b).
9. Writer contract (§9y): NULL never 0 for unreached stages; skip rows
   written under `none:<partner>`; gtin quartet NULL when the strategy
   didn't run.

10. **Prefer a STRUCTURAL positive control to a transient one**
    (operator's §60; ledger §61). A control that exists because of how
    the system is built cannot quietly stop controlling. brooklyn-delhi
    has no AWIN feed, so its 29 products permanently exercise the
    NULL-vintage exclusion branch. A control picked because a product
    "happens to be stale today" evaporates when someone fixes the
    staleness — and the test keeps passing while testing nothing.

11. **Every flag, kill-switch and suppression carries a pointer to its
    incident record AT ITS DEFINITION SITE** (operator's §61; ledger
    §62). Not in a commit message, not in a doc someone might find. The
    person deciding whether to flip it is looking at that line, and the
    reason it exists is the only thing that can stop them. Audited
    2026-08-22: 8 gated constructs, 4 pointers added (ledger §64). The
    audit must also cover **copy that depends on a flag** — the
    sparkline's "charts are on the way" is only true while the chart
    flag is on its way, and nothing connected the two.

12. **Provenance travels WITH the value, not alongside it** (operator's
    §62; ledger §63). Never derivable, never looked up separately by
    each surface. Two sources for one fact caused the 500/988
    stamp-vs-chart disagreement; the fix was making the price carry its
    own vintage end to end.

    *Numbering note:* the operator issued these as §60/§61/§62. The
    findings ledger already had a §60 (the chart restoration, same day),
    so they are recorded there as §61/§62/§63. "§60" unqualified means
    the chart. Flagged rather than silently renumbered — see ledger §61.

13. **A flag's blast radius includes the copy that assumes it** (ledger
    §67). Any user-visible sentence whose truth depends on a gated
    construct is registered at that construct's definition site, and the
    flag audit checks dependent copy, not just flags. Swept 2026-08-22:
    5 sites, 4 newly registered. The big one is `/categories`, where
    "Coming soon" renders 682 times against 78 real product counts and
    can never be flipped on.

14. **Merchant-facing verification requires a rendered check** (ledger
    §66). Text extraction from a storefront is a hypothesis, never a
    finding. WebFetch misreported both availability and price on
    tsarbomba.com.

15. **Never follow an AWIN `pclick.php` link to resolve a destination**
    (ledger §68). The redirect registers a self-click. Resolve
    `p=<id>` against the feed's `merchant_deep_link` column instead —
    which is also strictly stronger, because a `p` absent from the feed
    is invisible to a redirect-follow.

16. **Controls green does not mean the method is right** (ledger §68).
    A control proves the instrument can tell its two answers apart; it
    does not prove it is answering the right question. All three
    controls passed while a probe overstated dead links by 40%. When a
    check produces a dramatic number, re-derive it by a SECOND METHOD
    before reporting — re-running the controls is not that.

17. **A redirect that lands on a 200 has not necessarily succeeded**
    (ledger §70). Assert what you landed ON, never merely that you
    landed. Shopify redirects a deleted product handle to the homepage,
    which returns 200 — scoring that as a working link reported
    golden-maple's 6 dead links as 0 and tsar-bomba Default's 25 as 7.
    For a link check the destination's IDENTITY is the finding; the
    status code is not.

## 6. WHAT I GOT WRONG (so the successor isn't overconfident in the same places)

1. **The false-clean extractor (§19).** Hand-rolled a PDF parser,
   declared "exclusive assets…" absent, backed it with four positive
   controls — all drawn from the one font subset my decoder happened to
   fit. The controls were structurally incapable of failing. pdftotext
   was installed the whole time; I never checked. Lesson: the control
   must come from the population the claim is about, and use the real
   tool before writing one.
2. **tsar-bomba placeholder diagnosis named the wrong remedy (§21→§22).**
   I called 10 placeholder rows a stale-sync defect; they were baked
   into the static file (import-time download failures). The checker
   would have shipped pointing at the wrong fix if the comparison had
   stayed against a blanket zero instead of against what the data would
   produce.
3. **"Refreshed daily," written DURING the honesty pass (§27/§28).**
   The author of the standard violated it within hours; only the
   machine caught it. The class regenerates from ordinary language —
   which is why the claims tripwire is a blocking postbuild gate, not a
   memory.
4. **The narrative clock (open item C).** I "met" a before-11:00Z
   deadline at 15:12Z and reported it met, because I trusted my sense
   of elapsed time over a timestamp. Verify times from `git show`/`date -u`,
   not from the story so far.
5. A standing shape for all four: the confident wrong answer came
   where verification felt redundant. The findings ledger's §16–§19
   arc (silent caps, vacuous zeros) is the same lesson at system scale
   — read those two sections before trusting anything that "obviously
   works."
